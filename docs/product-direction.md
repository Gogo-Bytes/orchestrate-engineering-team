# 产品方向与边界

> 本文记录已确认的目标状态，是产品设计的权威入口；[实施代办](implementation-roadmap.md)记录进度和验收。当前源码尚未实现全部目标，不能把本文的目标表述为已发布能力。

## 产品目标

这是面向独立开发者和开发团队的开源项目准备工具包。它帮助新项目建立可用的工程基础，帮助已有仓库整理 Agent 入口、工程知识和验证路径，使 Agent 与人类工程师都能找到可信材料并完成后续开发。成功以项目约束得到保留、事实有代码或配置证据、本地检查可运行、普通开发任务无需重新进入设置流程来衡量；文件数量不是目标。匹配任务的读取量、token 和耗时用于优化基线，不以单次速度差作为发布结论。

首期公开交付以一个可从 GitHub 安装的 `prepare-engineering-project` Skill 为主。用户可将其安装到全局或目标项目，只有在用户显式调用 `$prepare-engineering-project` 时才运行。没有说明要写入时，默认先返回证据、冲突、风险和有边界的补丁方案；用户明确要求应用或初始化时，才在该请求范围内修改文件。完成准备后，日常开发使用目标项目自己的入口、代码、测试和按需 Skill，不由准备 Skill 接管任务流程。

## 用户路径与产物

| 情况 | Skill 的输入与行为 | 可交付结果 |
| --- | --- | --- |
| 已有仓库，技术栈不限 | 核对现有指令、代码、配置、测试和文档，区分现状、提案及冲突；先评估，按用户授权做小范围改造 | 简短的 Agent 入口、经证实的当前架构说明，以及确有检索价值时的模块导航；已有项目 Skill 首期只给强化建议 |
| 全新项目 | 先确认目标、约束、技术栈和运行方式；关键选择缺失时给少量建议并等待用户决定 | 首批在 Node/TypeScript 与 Python 两种受支持路径中建立最小仓库结构、人类与 Agent 入口、标明为提案的架构材料，以及实际可运行的本地检查；不生成业务首版 |
| 再次显式调用 | 对已建立的材料复查漂移、重复与失效链接，依据当前项目事实提出或应用获授权的小补丁 | 每次可验证的增量修订，而非自动收敛承诺 |

已有项目沿用有用的目录和术语，是否调整结构由用户决定。准备 Skill 不搬动或重构已有业务代码；此类工作属于独立开发任务。若用户拒绝任何写入，本次只能交付只读诊断与建议，旧指令继续生效，项目不会因此自动逐渐收敛。只有在用户允许修改项目入口时，才能加入“相关契约变化时更新材料”一类轻量日常提示；复杂整理仍需再次显式调用准备 Skill。渐进改进的可行性与额外成本必须用连续任务案例验证，不预设 Agent 能长期可靠地自行维护。

项目材料按职责安排，而非强制文件树：根 `AGENTS.md` 放简短路由与项目硬边界；当前架构说明只记录已确认的事实；尚未实现的设计明确标为提案；模块导航与项目专项 Skill 仅在有真实检索或方法价值时出现。工程事实优先由代码、类型、测试、模式和可执行配置承载，文档记录难以从这些载体恢复的约束与原因。

## 开源仓库的四层边界

| 层 | 内容 | 分发或运行边界 |
| --- | --- | --- |
| 用户安装包 | `.agents/skills/prepare-engineering-project/` 中的入口、元数据和必要资源 | 只安装这个 Skill 文件夹也能完成受支持任务；必需模板随 Skill 的 `assets/` 打包，专项方法按需放入 `references/`，不依赖运行时从本仓库获取 |
| 目标项目成果 | 用户仓库中获授权的指令、说明、验证配置及必要的项目 Skill | 适配项目事实与既有结构，不复制本产品的维护脚本或强制任务状态 |
| 可选工具 | 独立的 `oet` CLI | 只做可确定的盘点和结构检查；不生成项目语义，不是 Skill 的安装或运行前提 |
| 开源维护材料 | README、教程、贡献与安全说明、合成案例、评估和发布检查 | 服务于理解、贡献和验收本产品；不假定这些文件会到最终用户本地 |

首期以 GitHub 安装为主要渠道，只对 Codex 的安装、显式调用和行为案例给出验收保证；Skill 内容尽量保持通用，其他宿主需要单独验证调用策略。公开教程与可复现评估使用合成项目。pipeline 等工作流模板将来可作为用户选择的能力研究，首期不引入强制流水线、任务状态机或通用主编排器。目标项目默认只建立本地可运行的检查，不擅自生成特定代码托管平台的 CI 或部署配置。

## 当前源码与待决事项

当前工作区已有一个显式调用的准备 Skill、面向已有仓库的评估与文档改造指导、只读 `oet project inspect/check`，以及五个已有项目和后续普通开发的合成行为案例。Skill 目前仍提及可选 CLI；新项目只被识别为未来模式，尚无 Node/TypeScript 或 Python 初始化资源与验收案例。此前的编排产品移除工作仍在当前未提交工作区中，不能视作已发布版本。具体差距与实施顺序见[实施代办](implementation-roadmap.md)。

以下决定留在实施前确认，不由 Agent 擅自选择：

- **正式项目名称、Skill 名称和安装路径：待决。** 当前 `orchestrate-engineering-team`、`oet` 和 `prepare-engineering-project` 是开发名称；首个公开稳定版本前确定更名及兼容范围。
- **Node/TypeScript 与 Python 的具体工具链和版本：待决。** 两种路径都必须有可运行的本地检查，但依赖、包管理器和命令应在模板实施前明确并验证。
